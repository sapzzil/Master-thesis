## 목적

v4 계획서를 동결하기 전에 PC에서 세 가지 사실을 확인합니다.

1. 한국 5종목: 어떤 종목이 뽑히는지, 데이터가 온전한지 (`k01`)
2. 모델 6종이 v4 형태(내일 1일 예측, 과거 21/252일, 입력 수익률/가격)로 정상 작동하는지 (`k03`)
3. 1회 예측 시간과 본 실험 전체 예상 시간 (`k03`)

**실험이 아닙니다.** 결과를 해석하거나 논문을 고치지 않습니다.

## 규칙

1. 실제 주가로 모델을 돌리지 않습니다. k03은 가짜 데이터만 씁니다. 커버리지·정확도를 계산하지 않습니다.
2. 기존 파일(`src_v3`, `results_v3`, `data/raw`, `k02_model_timing.py`, `model_timing.csv`, `marcap-2017.parquet`)은 수정·삭제하지 않습니다. 새 파일은 `04_실험코드/data/raw_v4/`에만 만듭니다.
3. 환경은 `thesis_v4`(지난번에 만든 것)를 그대로 씁니다. 패키지를 새로 설치하거나 버전을 바꾸지 않습니다.
4. `k01`은 고치지 않습니다. `k03`은 모델 호출부(어댑터 클래스 안쪽)만 고칠 수 있고, 고쳤다면 전후 코드와 이유를 보고합니다.
5. 막히면 우회하지 말고 멈춰서 오류 메시지 그대로 보고합니다.

## 3. 모델 점검·시간 측정 (k03, 모델별로 따로)

**반드시 한 모델씩, 아래 순서대로 따로 실행합니다.** 한 번에 다 돌리지 않습니다. 이유는 두 가지입니다. 결과가 모델마다 바로 저장되고, 한 모델이 남긴 설정(예: 기본 장치 변경)이 다음 모델에 영향을 주지 않습니다.

```
python 04_실험코드/src_v4_prep/k03_model_check_v4.py --only moirai2          2>&1 | Tee-Object -FilePath 04_실험코드/data/raw_v4/log_k03_moirai2.txt
python 04_실험코드/src_v4_prep/k03_model_check_v4.py --only timesfm25        2>&1 | Tee-Object -FilePath 04_실험코드/data/raw_v4/log_k03_timesfm25.txt
python 04_실험코드/src_v4_prep/k03_model_check_v4.py --only chronos2         2>&1 | Tee-Object -FilePath 04_실험코드/data/raw_v4/log_k03_chronos2.txt
python 04_실험코드/src_v4_prep/k03_model_check_v4.py --only garch_t          2>&1 | Tee-Object -FilePath 04_실험코드/data/raw_v4/log_k03_garch_t.txt
python 04_실험코드/src_v4_prep/k03_model_check_v4.py --only chronos_t5_base  2>&1 | Tee-Object -FilePath 04_실험코드/data/raw_v4/log_k03_chronos_t5_base.txt
python 04_실험코드/src_v4_prep/k03_model_check_v4.py --only chronos_t5_large 2>&1 | Tee-Object -FilePath 04_실험코드/data/raw_v4/log_k03_chronos_t5_large.txt
```

- 각 실행은 결과를 `model_check_v4.csv`에 **조건 하나 끝날 때마다** 합쳐 저장하고, 마지막에 `projection_v4.csv`를 다시 씁니다.
- 스크립트가 알아서 하는 것 (손대지 않음):
  - GPU 메모리가 9,500MB를 넘거나(일반 RAM 빌려 쓰기 = 극저속) 메모리 부족 오류가 나면 더 작은 배치로 내립니다. 이때 `배치 16: 최대 메모리 ... → 더 작은 배치` 같은 줄이 찍히는 건 정상입니다.
  - 배치 시험 1회가 120초를 넘어도 더 작은 배치로 내립니다.
  - 1회 예측이 느리면 측정 횟수를 1,000 → 200 → 50으로 줄입니다.
- **예상 시간**: Moirai·TimesFM·Chronos-2·GARCH는 각각 수 분, Chronos-T5 base는 10~30분, large는 30~60분 정도입니다.
- **중단 기준**: 한 모델이 **60분이 넘었는데** 조건 4개 중 하나도 `{'model': ...}` 줄이 안 찍혔으면 Ctrl+C로 멈추고, 그 시점까지의 로그와 작업관리자 GPU 화면(전용·공유 메모리)을 보고합니다. 다음 모델은 계속 진행합니다.
- 오류(`ERR`, `LOAD ERR`)가 나도 다음 모델은 계속 진행합니다. 오류는 보고서에 그대로 붙입니다.
- Chronos-2에서 `cannot pin` 오류가 다시 나면: 공식 README 예제에 맞게 `Chronos2` 클래스 안쪽만 고쳐 한 번 더 시도하고, 그래도 안 되면 보고합니다.
