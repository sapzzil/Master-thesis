# v4 사후 점검 2 지시서 (2026-10-21) — Antigravity 실행용

## 목적

Chronos-T5에 대해 두 가지를 추가로 확인합니다. 미리 고정한 계획 밖의 점검이며, 결과가 어떻게 나오든 모두 보고합니다.

- e4: 원 논문 조건에 가까운 과거 길이 512에서 정규분포 계열(N(0,1), N(100,10²))의 커버리지(기본 샘플링 대 제한 해제)
- e5: 표본 수 200개 대 1,000개의 차이(합성 L1, 과거 252일, 수익률, 제한 해제)

**결과를 해석하거나 논문을 고치지 않습니다.**

## 규칙

1. 새 코드는 `04_실험코드/src_v4_post/post_checks2_v4.py` 하나뿐입니다(같은 폴더의 `post_checks_v4.py`를 불러 씁니다). 어떤 코드도 고치지 않습니다. 오류가 나면 우회하지 말고 멈춘 뒤 오류 메시지를 그대로 보고합니다.
2. 기존 결과는 읽기만 합니다. 새로 생기는 것은 `results_v4_post_smoke/`, `results_v4_post/` 안의 e4·e5 파일, 그리고 `04_실험코드/` 바로 아래의 로그 파일(`post2_*.txt`)뿐입니다.
3. 환경은 `thesis_v4` 그대로 씁니다. 패키지를 설치하거나 업그레이드하지 않습니다.
4. 모든 명령은 `04_실험코드/src_v4_post/` 폴더에서 실행합니다.

## 수정 사항 (2026-10-21 09:25)

첫 본 실행에서 e4가 과거 512일·배치 4로 GPU 메모리가 넘쳐 매우 느렸습니다(200회에 19분). 코드를 배치 1·계열 30개(e5는 계열 25개, 표본 1,000개는 배치 1)로 고쳤습니다.

- 실행 중인 e4를 중지합니다(Ctrl+C).
- `04_실험코드/results_v4_post/raw/` 안의 `e4__`로 시작하는 파일이 있으면 지웁니다(첫 실행이 저장한 파일은 없어야 정상).
- 아래 0의 지문을 새 값으로 확인한 뒤 **스모크는 건너뛰고 2(본 실행)부터** 다시 실행합니다.

## 0. 준비

```
conda activate thesis_v4
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$env:PYTHONIOENCODING="utf-8"
cd 04_실험코드\src_v4_post
Get-FileHash post_checks2_v4.py -Algorithm SHA256 | Format-Table Hash -AutoSize
```

지문이 `C2546F65EF313C8A7F95890196B22302A913305ADD427A59856739406346F914`인지 확인합니다. 다르면 멈추고 보고합니다.

## 1. 스모크 (약 3분)

```
python post_checks2_v4.py --exp e4 --smoke 2>&1 | Tee-Object -FilePath ..\post2_smoke_e4.txt
python post_checks2_v4.py --exp e5 --smoke 2>&1 | Tee-Object -FilePath ..\post2_smoke_e5.txt
```

두 명령이 모두 `[완료]`로 끝나고 오류가 없으면 **멈추지 말고 바로 2로 넘어갑니다.** 오류가 있으면 멈추고 보고합니다.

## 2. 본 실행 (약 30~40분)

```
python post_checks2_v4.py --exp e4 2>&1 | Tee-Object -FilePath ..\post2_e4.txt
python post_checks2_v4.py --exp e5 2>&1 | Tee-Object -FilePath ..\post2_e5.txt
```

- 중간에 끊기면 같은 명령을 다시 실행합니다. 이미 저장된 결과는 건너뜁니다.
